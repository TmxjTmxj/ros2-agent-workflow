# 为什么这次 Codex 跑通了，而 Hermes + DeepSeek 没有

这不是一篇模型排行榜，也不声称一次项目能代表所有环境。它记录的是同一台电脑、同一个 ROS2
医院送药任务里的可复核现象：此前的 Hermes + DeepSeek 尝试数小时仍未形成可验收闭环；随后
Codex 把任务改造成通用 Agent→MCP→ROS2 流程，并用自动化测试、独立里程计与真实 Gazebo
运行证据完成验收。

## 观察到的结果

| 对比项 | Hermes + DeepSeek 尝试 | 本仓库中的 Codex 流程 |
|---|---|---|
| 任务理解 | 能读取文件、分析 ROS2 配置 | 读取交接文档并把赛题约束固化为 profile、测试和验收器 |
| 控制闭环 | 没有在当次尝试中稳定跑通“启动→控制→验证→清理” | MCP 工具只表达意图，RuntimeController 独占控制权并执行安全状态机 |
| 排障方式 | 长时间停留在调研和局部尝试，缺少确定的完成判据 | 每个缺陷先写失败回归，再修复，最后跑真实 Gazebo 验收 |
| ROS2 进程管理 | 未形成可证明的单实例与精确清理 | 记录 PID/PGID/进程身份，失败时隔离，退出后检查残留进程 |
| 证据 | 没有生成足以证明赛题完成的独立证据包 | 独立 `/odom`、控制器 GID、五路接触源、前后相机 PNG、停止漂移与 JSON 报告 |
| 最终状态 | 数小时内未完成 | 官方 TurtleBot3 Burger 模型完成三段配送；结果以仓库中的验收报告为准 |

这里的“成功”不是终端里出现一句 `SUCCEEDED`。它要求任务状态、独立里程计、碰撞监控、
单控制器身份、停止后的稳定性、截图和进程清理同时成立。任一条件缺失都判定为失败。

## 真正产生差异的四件事

### 1. 把自然语言目标变成了可执行契约

“让车跑完三段路线”太模糊。Codex 流程把它拆成机器人 profile、任务 profile、能力发现、
参数校验、武装授权、启动、监控、急停和证据导出。速度上限、坐标系、终点容差、接触源与
清理时限都进入机器可读配置和测试，不再依赖 Agent 临场猜测。

### 2. Agent 不直接发布运动命令

语言模型只通过 12 个受限 MCP 工具提交高层意图。真正的运动控制由单写入者运行时负责；
安全授权带有代次和所有权，急停、审计、超时与清理采用 fail-closed 语义。这样既保留 Agent
的规划能力，也不让一次错误工具调用绕过 ROS2 安全边界。

### 3. 排障形成了“观察—假设—回归—实跑”循环

仿真项目最难的部分不是生成一段 ROS2 代码，而是跨越模型几何、坐标变换、控制器、DDS、
进程生命周期和证据采集持续收敛。本项目对每个发现先制造确定性失败，再写最小修复；静态测试
通过后仍要重新构建并完整跑一次 Gazebo。Codex 在同一工作区里维持了这条长链，而此前尝试
没有收敛到一个可重复的验收门禁。

### 4. 视觉有帮助，但独立数值证据更重要

Codex 能检查 Gazebo 相机图像，这对发现模型、场景和视角问题有帮助；Hermes 当时缺少这条
视觉反馈。不过，不能把差异简单归因于“有没有眼睛”。最终判定主要依赖独立里程计、发布者
身份、接触消息、停止漂移和进程残留。截图是证据的一部分，不是替代物。

## 可迁移的通用方案

```text
自然语言任务
    ↓
Codex / 其他 Agent
    ↓  仅调用受限 MCP 工具
能力发现 → profile 校验 → 安全授权 → 任务执行 → 持续监控
    ↓                                      ↓
RuntimeController（单写入者）       watchdog / ESTOP / 审计
    ↓
ROS2 adapter（Twist、Nav2 或受控的固定 lifecycle）
    ↓
机器人或 Gazebo
    ↓
独立验收器（里程计、碰撞、GID、图像、清理）
```

迁移到另一台机器人时，应更换 robot profile 和 adapter，而不是让 Agent 修改安全内核。迁移到
另一项任务时，应更换 task profile 和独立验收规则。只有新硬件确实缺少标准接口时，才新增经过
审查的 adapter。

## 应该怎样解读这次对比

- 这次结果证明的是一个具体工程路径可行，不证明某个模型在所有任务中必然胜出。
- Codex 的优势来自长程执行能力与工作区工具，也来自本仓库建立的受限接口、测试和独立证据；
  不是只靠模型品牌。
- Hermes + DeepSeek 的失败是这次具体尝试没有闭环，不等于它们不能承担检索、局部修改或
  独立复核等边界清晰的工作。
- 第二个 Agent 的审查可以发现问题，但审查结论仍须通过代码、测试和真实运行验证，不能直接
  当作事实写入项目。
